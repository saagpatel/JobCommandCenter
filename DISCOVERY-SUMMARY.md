# Job Command Center — Discovery Summary

## Problem Statement

The job search pipeline has three bottlenecks: (1) submitting applications is manual — 30+ minutes per batch of 5-8 apps across multiple ATS platforms, each requiring form filling, file uploads, and toggle clicking. (2) Tracking application status lives in a Claude.ai artifact with fragile `window.storage` persistence — no real database, no analytics, no integration with the rest of the pipeline. (3) Follow-up emails, interview prep, and pipeline visibility require manual effort across disconnected tools (Gmail, Google Docs, the artifact tracker). The upstream pipeline (job research → Cowork doc generation) is already automated. The downstream pipeline (tracking → follow-ups → interview prep → analytics) is entirely manual.

## Target User

Solo job searcher (you) applying to 5-10 roles per batch, 1-2 batches per week. Currently targeting Senior IT / Head of IT / IT Engineering roles at Bay Area tech companies. Tailored resumes and cover letters already exist in `~/job-search-2026/{Company}/` as PDF + DOCX pairs generated by Cowork.

## Success Metrics

- Full batch of 8 applications submitted via one command in < 10 minutes (API-direct < 10s each, Playwright < 90s each)
- Tracker shows real-time status across all applications with zero manual data entry after submission
- Follow-up email drafts auto-generated at +7 days, requiring only user review and send confirmation
- Interview prep brief auto-generated when status changes to "Interview," pulling company context + role details
- Pipeline analytics: applications sent, response rate, time-to-response, conversion funnel
- Zero credentials in plaintext anywhere — all secrets in macOS Keychain

## Scope Boundaries

**In scope:**

- Job tracker with Kanban board (Saved → Applied → Interviewing → Offer → Rejected → Archived)
- Batch submission engine: Ashby API, Greenhouse API, LinkedIn Easy Apply, Indeed Apply, Gem/Workday/generic Playwright
- Applicant profile management (reusable across batches)
- Resume/cover letter file linking to `~/job-search-2026/` directory
- Follow-up email drafting via Claude API + sending via Gmail API
- Interview prep brief generation via Claude API
- Submission analytics dashboard
- Per-company notes and timeline
- Settings page for credentials, profile, preferences
- Sidecar health monitoring and log streaming in the UI

**Out of scope:**

- Job discovery / scraping (curated manually, pasted as URLs)
- Resume / cover letter generation (handled by Cowork, separate tool)
- Interview scheduling / calendar integration
- Salary negotiation tracking
- Multi-user / collaborative features
- Mobile app
- ATS account creation (one-time manual setup for Workday, Indeed)

**Deferred to later phases:**

- Lever API adapter (Phase 5 — when Lever listings appear)
- Gmail inbox scanning for auto-detecting responses/rejections (Phase 5)
- Bulk import from LinkedIn saved jobs (Phase 5)
- Chrome extension for "Save to Job Command Center" from any careers page (Phase 6)

## Technical Constraints

- macOS only (Tauri WebView, Keychain, Playwright Chromium)
- M4 Pro / M3 machines (ARM64 — PyInstaller must target aarch64-apple-darwin)
- Files read from `~/job-search-2026/` — existing Cowork output structure, read-only
- Playwright runs headed (not headless) — anti-bot-detection requirement
- No cloud infrastructure — everything runs locally
- LinkedIn and Indeed require authenticated browser sessions — first login is manual, then session is persisted via Playwright's `launch_persistent_context()`
- Anthropic API key required for Claude features — stored in Keychain
- Google OAuth2 credentials required for Gmail — one-time browser auth flow, token stored in app data directory
